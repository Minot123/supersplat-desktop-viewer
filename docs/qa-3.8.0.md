## Native Round-Trip Method

`scripts/qa-native-roundtrip.mjs` opens a source through the native file resolver, applies committed color/transparency edits, exports PLY and SOG through the Editor, and saves SSPROJ through its document API. Files are reopened through the desktop shell. A second PLY cycle and a second SSPROJ save through native HTTP PUT check cumulative drift. SSPROJ background and anti-alias settings are checked after reopening.

The test uses a fixed camera and 640 x 480 offscreen renders, explicit ACES2 tonemapping, antialiasing on and stochastic rendering disabled. PLY/SOG do not carry the editor background/camera settings, so those are reapplied for comparison; SSPROJ must restore them itself. SOG uses one compression iteration in this test, with a separate lossy comparison tolerance.

Image deltas are mean absolute RGB differences on the 0-255 scale. The gradient fixture uses a 0.01 threshold for project/repeated saves. SH3 reloads showed a small, non-cumulative color variation of about 0.026 (including a second project cycle returning to within 0.00015 of the original). The final SH3 threshold is 0.05, with a separate strict 0.01 alpha/DC-only project check. A PLY first export allows 0.1; lossy SOG allows 3. Camera, view settings, model transform and committed color palettes must also match exactly for SSPROJ. Earlier results rejected by the stricter SH threshold remain in the scratch reports rather than being discarded.

UI checks cover a closed startup menu, Orbit controls, hidden Viewer overlays, rotation, FOV, Reset and three Viewer/Editor round trips preserving the scene object and camera.

The generated fixture has 4,096 splats and a continuous opacity/color gradient. The private large fixture has 3,000,000 splats, SH3, 744,001,762 bytes. Its original SHA-256 remained unchanged. Its name, identifying checksum and filesystem location are retained only in local QA evidence.

## Stress-Test Findings

An early large-project save crashed WebView2. A locally retained Crashpad dump records exception `0xE0000008` and an attempted allocation of 771,006,464 bytes. This is the 771,003,320-byte archive rounded to allocation alignment. Chromium defines this exception as out of memory: [allocator source](https://chromium.googlesource.com/chromium/src/base/+/dfae0d5907632e6ae9ff5720f0700a51277f2fcd/allocator/partition_allocator/src/partition_alloc/oom.h).

The download writer used a MemoryFileSystem that concatenated its buffered chunks into another whole-file Uint8Array. Native project PUT also converted a Blob back into an ArrayBuffer before making a second Blob. Both redundant whole-file copies were removed. Blob-backed export still requires memory/storage for the output; this is not a guarantee that arbitrary-size scenes fit on every machine.

An early comparison also used the unsupported tonemapping name `none`. The test now sets and checks `aces2` explicitly, and uses the current string-valued stochastic mode `disabled`. Earlier comparisons made with different effective view settings are not used as final render-equivalence evidence.

Repeated stress-test exports reduced drive D free space to about 4.6 GiB. A later project fetch failed with `net::ERR_FAILED` after the PUT had completed. After removing only generated test exports and using a fresh test WebView profile, the full reopen/overwrite checks passed. Keep sufficient free disk space for WebView Blob storage as well as the output files; this test does not establish the precise internal Chromium quota that caused that fetch failure.

## Boundaries

- Exact bitwise PNG equality is not required: GPU packing and SH re-quantization can produce small differences. SOG is lossy and may remove negligible-opacity splats.
- Values above one are preserved in PLY data; the upstream projected renderer still clamps displayed alpha to one before AA. This build does not claim expanded-range opacity rendering.
- The legacy standalone fallback stays at 1.31.2. Primary Viewer and Editor share the updated Editor renderer.
- Existing upstream Sass deprecation and mediabunny bundling warnings remain non-fatal.
